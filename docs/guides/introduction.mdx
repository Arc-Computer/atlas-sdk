# Getting Started with Atlas SDK

Atlas wraps your existing agent with a dual-agent learning system. The onboarding flow takes you from installation to collecting training data in under 5 minutes:

```bash
pip install arc-atlas
export ANTHROPIC_API_KEY=sk-ant-...
atlas env init
atlas run --task "Your task here"
```

## What `atlas env init` Does

The initialization command discovers your agent and generates production-ready configuration:

1. **Scans your codebase** for agent classes (decorated with `@agent` or matching agent patterns)
2. **Selects the best candidate** using LLM-based analysis of your code structure
3. **Generates Atlas configuration** using Anthropic defaults:
   - Student: Claude Haiku 4.5 (fast, cost-effective)
   - Teacher: Claude Sonnet 4.5 (powerful, accurate)
   - Learning: Few-shot prompting + playbook injection enabled
4. **Sets up PostgreSQL storage** (optional, via Docker) for training data persistence

The entire process requires zero manual intervention. The generated configuration is saved to `.atlas/generated_config.yaml` and uses defaults optimized from runtime evaluation benchmarks (0.989 reward score, 20.08s average latency).

## Generated Files

After running `atlas env init`, you'll have:

- `.atlas/generated_config.yaml` – Atlas runtime configuration with Anthropic defaults
- `.atlas/generated_factories.py` – Adapter factories for your agent (if needed)

## Custom Providers

While the default uses Anthropic models for optimal performance, you can edit `.atlas/generated_config.yaml` to use any supported provider (OpenAI, Google, Gemini, xAI, Bedrock).

## Training Data Access

Once storage is configured, runtime sessions stream to PostgreSQL automatically. Use the training data API to access sessions for model training:

```python
from atlas.training_data import get_training_sessions

sessions = get_training_sessions(
    db_url="postgresql://atlas:atlas@localhost:5433/atlas",
    min_reward=0.7,
    review_status_filters=["approved"],
    limit=100
)
```

See the [Learning Evaluation](docs/evaluation/learning_eval.md) guide for details on using learning reports to track reward deltas and adaptive mode shifts over time.

## Leaner paired-mode validation

Paired mode now ships with a compact `validation_request` envelope. Heavy fields—artifacts, full structured outputs, and prior
step transcripts—are stored once per session inside the execution context and validation requests now include each blob’s
content alongside a stable digest. When a retry produces the same structured output, the orchestrator reuses the cached verdict instead of sending the
teacher back to the LLM. Telemetry exports are unchanged: they still record the full structured output, validation result,
and `cached` provenance flag so the learning harness continues to receive identical signals.
